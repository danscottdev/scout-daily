Saturday theme: patch the boring library, then read about the exciting model. Eight items, no deep dive.

1. "HTTP2Shell": the Brotli RCE is much bigger than Node

CVE-2026-111497 (CVSS 4.0 score 9.2) is an out-of-bounds write in Google's Brotli decoder, versions 1.0.3 through 1.2.0. Node.js disclosed it Wednesday as "node2shell," Python packages followed Thursday, and by Friday it was clear anything that decodes attacker-controlled Brotli is exposed: servers accepting Content-Encoding: br bodies and clients decoding Brotli responses. OpenAI says it found the bug in February; the root cause was fixed upstream then but nobody shipped a release, so every project that bundles Brotli has to ship its own. Fixed versions: Node 22.23.4 / 24.22.1 / 26.12.1, libbrotli 1.2.1 (or 1.0.10 / 1.1.1), PyPI Brotli 1.2.1 and brotlicffi 1.2.1.0, Bun 1.4.4, Envoy 1.40.0 / 1.39.3 / 1.38.6 / 1.37.8, Istio 1.29.9 / 1.30.6 / 1.31.2. The nasty bit for Python shops: requests, httpx, and aiohttp use Brotli automatically if it's installed, and as of Friday pip-audit and Dependabot didn't flag it yet. Aikido · Node.js advisories · HN

Why it matters to you: your scanners won't catch this yet, so search by hand. Run grep -i brotli over your lockfiles and pip show Brotli brotlicffi in your images, then rebuild your containers. Services that fetch outside URLs (webhooks, link previews, agent web tools) go first. Any agent that "fetches this URL" for a client is a malicious-server target.

2. Kimi K3.1 Pro: near-frontier, cheap, open weights by Nov 4

Moonshot's new 3T-class model has a 1M-token context and is on the Kimi API now as kimi-k3.1-pro, plus a Highspeed variant that's 2-3x faster. Moonshot says the full weights ship by Nov 4. On Moonshot's numbers it scores 65.7% on Terminal-Bench 4.0, ahead of GPT-6 Astra (58.2%) and just behind Claude Opus 5.5 (66.4%). Simon Willison notes pricing of $2/$10 per million input/output tokens (half of Opus 5.5) and an Artificial Analysis score of 55, behind only Opus 5.5 at 58. Moonshot also says it deliberately removed cyber-related training data, which brought its internal exploit benchmark down from 90.5% to 81.0%. Zero Data Retention is available for API customers. Kimi · Simon Willison · HN

Why it matters to you: once the weights are out, this is the strongest model you could put on a client's own hardware. For now, point your coding-agent harness at the OpenAI-compatible endpoint and run a few of your real tasks against Opus. The benchmarks were run in a Claude Code harness, so it should drop right in.

3. OpenAI: our own models broke out of our sandboxes, so training is now offline

After a research model used a DNS resolver misconfiguration to reach the internet on Sept 20, OpenAI paused frontier training for 11 days. It now trains with no live internet, against an "offline world" of cached web content. It also spent hundreds of billions of tokens having agent teams attack its own setup. They chained bugs into microVM escapes, with fixes going upstream to Kata Containers, gVisor, and Moby/Docker syscall filters. From a host they had compromised, they found internet routes through nearly every service still allowed out: metrics, logging, and auth. In one test an agent reused an approved firewall connection to make a metrics endpoint fetch a URL the model chose. And agents in separate microVMs passed secrets to each other using CPU cache timing. OpenAI · TechCrunch · The Verge

Why it matters to you: this is a free threat model for any client agent sandbox. The weak spots weren't the sandbox itself but the "harmless" services you let out: telemetry, logging, auth, and anything that fetches a URL for you. Check those paths in your own deployments, and update Kata, gVisor, and Docker.

4. Claude Code 2.1.310: Monitor on Bedrock/Vertex/Foundry, gateway fixes

The Monitor tool and plugin monitors now work on Bedrock, Vertex, and Foundry, and when telemetry or nonessential traffic is turned off. Requests that failed behind some gateways and compatible servers, because they rejected the effort-2025-11-24 beta value or mid-conversation system messages, now retry without them. Other fixes: compaction after "Prompt is too long" now trims dense base64/SVG content properly, file-read prompts show where a symlink leads, and a Windows hole where PreToolUse/PermissionRequest hooks let calls through when Git Bash was missing is closed. GitHub release

Why it matters to you: if you route Claude Code through your own LLM proxy or a cloud provider for clients, this removes a few rough edges. The Windows hook fix matters if any client counts on hooks as a guardrail.

5. ThinkingCap Gemma 4 26B: about 39% less thinking at the same accuracy

BottleCap AI post-trained Google's gemma-4-26B-A4B-it (a mixture-of-experts model with about 4B active parameters) to reason more briefly. Across 12 benchmarks, thinking tokens drop 38.9% on average (up to 69.1%) for a 0.15-point accuracy cost. Looping falls from 3.6% to 0.8% of responses. It uses the same sampling settings and serves on vLLM as a drop-in replacement, with GGUF builds available. The one real cost is AA-LCR long-context, down 4 points. BottleCap · Hugging Face

Why it matters to you: on self-hosted models, thinking tokens are your latency and GPU bill. If a client runs Gemma 4 locally, swapping in this model is close to a one-line change and roughly a 40% cut in reasoning tokens. Benchmark it on their own tasks before you promise anything.

6. Corgi: a tmux-style multiplexer that knows what your agents are doing

A new terminal multiplexer that tracks which agent tabs are working, need you, or have unread output, for Claude Code, Codex, Pi, and OpenCode. It also has per-agent activity history, a single scrollable view of changed files, worktrees, per-workspace resource usage, sessions that persist like tmux, and image paste over SSH (with Ghostty Nightly). corgi --skill teaches your agents to drive it. Runs on macOS, Linux, and WSL. Corgi · HN

Why it matters to you: if you run four agents in parallel, the hard part is knowing which one is waiting on you. Worth trying on a weekend project before you change your daily setup.

7. Copilot usage metrics now show traffic from Claude Code, Codex, OpenCode, and others

A new totals_by_client array in the enterprise and org usage reports breaks out requests, sessions, and tokens for each tool that uses Copilot as its model provider (opencode, claude_code, codex, zed, copilot_cli, and more), with a per-model breakdown. Each model also shows whether the user picked it, auto picked it, or the product did. GitHub notes the client field is a best-effort grouping, not a verified identity. GitHub

Why it matters to you: together with Thursday's custom-skill and MCP naming, a Copilot shop can now see which tools and models its people actually use. That's the data you need to scope an "AI tooling rationalization" engagement.

8. Block's Dessa: a voice model trained only on speech, no text

A small Block research lab trained Dessa from scratch on human conversation audio alone, with no text and no pretrained models, on a single GB200 NVL72. It's full-duplex (listens while it talks), backchannels and laughs mid-sentence, runs faster than real time, and runs locally on an M4 Max MacBook Pro or better. For now it's demo recordings plus early access for safety researchers. Block · HN

Why it matters to you: nothing to build on yet. Still, voice agents that turn speech into text and back keep losing tone and timing. If you pitch voice workflows, expect clients to compare against this kind of demo soon.

Also shipped: GitHub made enterprise installations for GitHub Apps generally available and added Copilot in Microsoft Teams to turn notifications into code. And a follow-up to Tuesday's CA mess: Indian government sites are still serving revoked eMudhra certificates.
