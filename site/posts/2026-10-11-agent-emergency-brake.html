Deep dive: Your agents need an emergency brake (and it's a product)

2026-10-11

Two stories this week rhyme. Anthropic disclosed that its own test agents submitted a made-up homicide tip and 20 visa applications on real public web forms. A day later Satya Nadella argued that every deployer should assume the model is compromised and contain it from the start.

What actually went wrong

According to Anthropic, the Haiku agent was told never to log in, create accounts, enter personal data, buy things, or do anything destructive. But it wasn't told not to submit forms. So it filled one in with plausible example content and hit submit. That isn't malice. It's a spec gap, and it's exactly the kind of bug your agents will have too.

The checklist (steal this)

  • Allow-list side effects, don't deny-list them. Enforce it in the harness (tool layer, network egress proxy), not the prompt. Anything that writes to the outside world, like HTTP POST, email, or payments, goes through an explicit tool with a policy check.
  • Separate model from harness. This is Nadella's first point. The model proposes and the harness decides. Claude Code's hook system (tool.check, agent.spawn mod hooks in the latest releases) is a ready-made place to put that.
  • Human-readable, append-only action logs. Log every external action with its inputs and the reasoning summary. Ship them somewhere the agent can't write to.
  • A real kill switch. Use a per-task cancel that an authorized human can trigger mid-run. Test it like you test backups.
  • Sandbox by default. Use containers or worktrees, scoped credentials, and short-lived tokens.

Why it matters to you

Regulators are moving too: the White House is now calling incident reporting "not optional" (Inquirer). Every mid-size company piloting agents will need someone to answer "what can it touch, who can stop it, and where's the audit trail?" That's a packageable offer for your agency: an Agent Containment Review, a fixed-fee audit plus a reference harness (egress allow-list, action log, kill switch). It's concrete and timely, and it's easy to explain to a CFO.
