Deep dive: own the LLM traffic layer (and sell it as a first engagement)

2026-10-19

Three things in the last week point at the same gap. Accenture capped centrally funded Claude spend at $29 per employee per month after some people hit about $1,000 (404 Media). Vercel shipped budgets per API key, project, person, and team in its AI Gateway (Ship recap). And DeepSeek just announced that search and fetch calls made by Claude Code and Codex sessions running on its models, free today, start billing at noon ET on Oct 31 (pricing). Meanwhile Jared Siegel's proxy rant hit the HN front page with one question: if all your LLM traffic goes straight from tools to vendors, how do you know what's going on?

Mostly, you don't. Without that layer you can see the monthly bill, but not which agent, key, or workflow drove it, or why one day's runs cost far more than the day before.

What the layer actually is

It's one HTTP endpoint you control, sitting between every client (IDE agents, CLI agents, internal apps, CI jobs) and every provider. Clients use a virtual key issued by the proxy; the real provider keys live only in the proxy. That one move gets you most of Siegel's list: one endpoint across providers and models, a log of who called what and with what result, no main key copied into every harness, and the ability to swap providers without touching each client.

Siegel deliberately doesn't recommend a product, and neither will I. Self-hosted open-source proxies and managed gateways like Vercel's both exist. The choice is mostly about where logs may live (client data policy) and whether you need to change the code. What matters is the data you collect.

The minimum log schema

Per request, record:

  • Who: virtual key, person or service, client/harness name and version (from the User-Agent or a header you require).
  • What: provider, model, effort or reasoning setting, streaming or not.
  • Cost drivers: input, output, and cached-input tokens, plus a computed dollar cost from a price table you version.
  • Outcome: HTTP status, latency, time to first token, retries, and the error class.
  • Tool calls: any server-side tool usage (search, fetch, code execution) as separate billable line items. The DeepSeek change is exactly the kind of cost that hides here.
  • Correlation: a session or run ID passed through from the agent, so you can rebuild one agent run end to end.

Whether to store prompt and response bodies is a policy decision, not a default. Hash them for dedup and cache analysis, and keep full bodies only where the client's data-handling rules allow.

Cache-miss forensics is the killer feature

Siegel's best line is that he can tell why a coding session missed the cache in 20 seconds. That matters because cache hit rate is one of the biggest cost levers in agent work, and it breaks silently. Last week's Claude Code changelog alone fixed a prompt cache miss when a tool added mid-session was reloaded through ToolSearch or after compaction (2.1.302), and OpenAI's Codex team has been tuning cache reuse across subagents (covered in yesterday's edition). If you log cached versus uncached input tokens per request and per session, a hit-rate drop after a tool upgrade shows up as a chart, not as a surprise invoice.

Budgets: enforce at the layer, not in a memo

Accenture's cap shows how this goes without the layer: a policy email, then overages pushed onto project budgets. With a proxy, budgets are config. Set soft limits that alert, hard limits that reject or downgrade to a cheaper model, and per-project keys so spend lands on the right budget automatically. Add per-run ceilings for unattended agents, the same instinct as the Claude Code usage-limit retry watchdog from yesterday's edition.

Rollout plan I'd actually use

  1. Week 1, observe only. Stand up the proxy, issue virtual keys to one team, and route their agents through it with no limits. Build three views: spend by person/project/model, cache hit rate by client and harness, and error/retry rate.
  2. Week 2, close the side doors. Rotate the real provider keys so the proxy is the only path. Add the price table and alert thresholds.
  3. Week 3, enforce and route. Turn on soft budgets, then hard ones. Try a routing rule or two (for example, a cheaper model for summarization or lint-fix subagents) and compare quality and cost against the logs you already have.

Two cautions. A proxy is now on the critical path for every agent, so run it highly available and fail clearly, not silently, when it's down. And it holds every real provider key, so treat it like a secrets system: network-restricted, audited, and owned by someone.

Why this is a good first engagement to sell

It's small, it's measurable, and it pays for itself in the client's own numbers. The output is a dashboard the CFO understands and an engineering team that can finally answer "which agent is expensive and why." It also sets up the next projects naturally: model routing, eval-driven model swaps (Replit just flipped its default provider on cost and partnership), and governance for the agent fleets they're about to run. Lead with the observe-only week. Once a client sees their own cache-miss chart, the rest of the plan usually sells itself.
